# Audit {{es}} HTTP request bodies [auditing-search-queries]

{{es}} can include the body of an authenticated REST request in its `authentication_success` audit event. Request bodies can contain search queries, indexing operations, security configuration changes, or payloads sent to other REST APIs.

:::{note}
:applies_to: stack: preview 9.4

To trace and analyze queries, use [query logging](/deploy-manage/monitor/logging-configuration/query-logs.md). Request body auditing can capture query payloads, but it associates the HTTP body with a security audit event and doesn't provide query-specific fields such as duration, outcome, or targeted indices. If query logging isn't available, request body auditing can help identify submitted queries.
:::

## Include request bodies in audit events

To include request bodies, configure the following setting in {{es}}:

```yaml
xpack.security.audit.logfile.events.emit_request_body: true
```

You can apply this setting through [cluster update settings API]({{es-apis}}operation/operation-cluster-put-settings), as described in [](./configuring-audit-logs.md). Alternatively, you can modify [`elasticsearch.yml`](/deploy-manage/stack-settings.md) in all nodes and restart for the changes to take effect.

The request body is available only on the `authentication_success` event generated by the REST layer on the coordinating node. This event isn't included by default. Add `authentication_success` to the existing `xpack.security.audit.logfile.events.include` list to capture request bodies while preserving the other event types that you audit.

::::{important}
Request bodies can contain sensitive data. Although {{es}} filters credentials from audited security APIs, other sensitive data might be recorded in plain text. A request body can also contain malicious content that breaks a parser consuming the audit logs.
::::

## Request body fields

How {{es}} records the request body depends on its content type:

`request.body`
:   For request bodies that {{es}} can represent as JSON, contains the full body as an escaped JSON string. {{es}} converts supported structured formats, such as YAML, to JSON. If you collect audit logs with the {{es}} integration or the {{filebeat}} {{es}} module, the ingest pipeline maps `request.body` to the {{product.ecs}} field `http.request.body.content` in indexed documents.

`request.raw_body` {applies_to}`stack: ga 9.4`
:   Contains the request body as a Base64-encoded string when {{es}} can't represent it as JSON, such as for Protobuf telemetry payloads. {{es}} emits this field instead of `request.body`. The audit event records the content type in `request.raw_body_content_type`. If the request specifies a content encoding, the audit event records it in `request.raw_body_content_encoding`.

For complete field descriptions, refer to [audit event types](elasticsearch://reference/elasticsearch/elasticsearch-audit-events.md).
